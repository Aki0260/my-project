# プロジェクト管理ツール - 仕様書

## 目的

個人で使うプロジェクト管理ツール。まずはMVPとして、プロジェクト・WBS・ToDo・工数・余日差・ダッシュボードを管理する。

## 全体構造

プロジェクト → WBS → ToDo → 作業記録（実績工数）

---

## 2. WBS管理

### 役割

WBSは「プロジェクトを作業構成に分解するもの」。親子関係を持たせ、ツリー形式で表示する。

### WBS画面

プロジェクト詳細からWBSを開き、親WBS・子WBSをツリー表示する。

### WBS作成項目

- WBS名：必須
- 親WBS：任意
- ステータス：必須
- 開始日：任意
- 終了予定日：任意
- 予定工数：任意

### WBS詳細

- WBS情報
- 予定工数
- 実績工数
- 進捗率
- 関連ToDo一覧
- ToDo追加

### WBSテーブル想定

- id
- project_id
- parent_id
- name
- status
- start_date
- planned_end_date
- planned_hours
- actual_hours
- sort_order
- created_at
- updated_at

### WBSとToDoの役割分担

- WBS：何の作業をするかを大きく整理
- ToDo：具体的に何をするかを管理

## 3. ToDo管理

### ToDoへの導線

2つの入口を用意する。

1. WBS詳細 → 関連ToDo
2. プロジェクト詳細 → ToDo（プロジェクト内のToDoを横断して確認）

### ToDo作成項目

- タスク名：必須
- WBS：必須
- ステータス：必須
- 優先度：必須
- 期限：任意
- 予定工数：任意
- 説明：任意

### ステータス

- 未着手
- 進行中
- 完了

開始日は持たせず、期限を中心に管理する方針。

## 4. 工数管理・余日差

### 工数の基本単位

アプリ内部では「時間」を基準単位にする。

- 予定工数：時間
- 実績工数：時間
- 残工数：時間

将来的に「日」単位で表示できるようにするが、DBの基準値は時間のままとする。

### 実績工数の記録

ToDo単位で実績工数を記録する。

作業記録は「作業日＋時間」を持ち、複数回の記録を積み上げてToDoの実績工数を算出する。

例：

- 8/10：1.0h
- 8/11：0.5h
- 8/12：1.0h
- 実績合計：2.5h

### 作業記録テーブル想定

- id
- todo_id
- work_date
- hours
- memo
- created_at

### 工数の集計

ToDo → WBS → プロジェクトの順に工数を集計する。

- WBS：ToDoの予定・実績工数を集計
- プロジェクト：WBS/ToDoの予定・実績工数を集計

## 5. 余日差

### 目的

「期限までに残り作業を終えられるのか」を一目で判断できるようにする。

### 見せる情報

- 予定工数
- 実績工数
- 残工数
- 期限までの日数
- 余日差

### 表示例

- 🟢 +4.0日：余裕あり
- 🟡 +0.5日：ほぼ予定通り
- 🔴 -2.0日：遅延リスク

WBS単位でも余日差を確認でき、「どこが危ないか」まで分かるようにする。

### 余日差の考え方

単純な残日数ではなく、期限までに実際に確保できる作業時間を基準にする。

---

## 6. 1日あたりの作業可能時間

### 基本設定

通常の1日あたり作業可能時間をデフォルトとして設定する。

曜日ごとの基本作業時間も設定可能とする想定。

### 日別調整

予定・休暇などがある日だけ、作業可能時間を個別に変更できる。

例：

- 通常：2h
- 予定のある日：1h
- 休日：0h

これにより、期限までの「実際に確保できる作業時間」を計算する。

### 余日差への利用

残工数と期限までの実作業可能時間を比較し、余裕・不足を日単位で表示する。
